# Curated global systematics: what `additional_systematics` carries, and where each number comes from

`build_tables.py` writes one `sys,<source>` column pair per entry of `additional_systematics` in a ratio block
(`frac * |y|` per bin; an asymmetric `[low, high]` pair is `[minus, plus]`, the HEPData `asymerror` orientation).
These are the global uncertainties HEPData does **not** publish as per-bin error labels: they are stated in a table's
prose `description`, in a dependent-variable `qualifier`, or occasionally as a constant per-bin error column that is
lifted into a named global. **None of the values below required reading a paper**: every one is quoted verbatim from the
HEPData record in the local `hard-sector-data-curation` mirror, and the config comment next to each entry cites the text.

uncertainties, so the absence of a global column there is correct.

bin-by-bin on 83 of the 92 paper observables; the 9 residuals are STAT-side (dropped PHENIX columns, a label convention on
STAR charged hadrons, and STAT's own `[0.010, 0.10]` transcription typo for CMS 2.76 TeV jets 30-50%).

## How to add another one

```yaml
tables:
  - parameters: { ... }
    # <quote the HEPData description / qualifier verbatim here, with the record and table>
    systematics_names: {stat: stat, sys: sys}
    additional_systematics: {}
    table: Table N
    combinations:
      - parameters: { centrality: "0_5" }
        index: "1"
        additional_systematics: { norm: 0.022 }          # symmetric fraction
      - parameters: { centrality: "20_30" }
        index: "3"
        additional_systematics: { norm: [0.20, 0.18] }   # [low, high] = [minus, plus]
```
A combination-level `additional_systematics` **replaces** the entry-level one, so list every source in each combination.
Use the HEPData number verbatim; do not back-compute a component the record does not publish separately (e.g. do not
split STAR's N_bin ⊕ pp-reference band). Rows: for pT-differential R_AA the writer keeps only the HEPData bins overlapping
the analyzer window (`hadron.pt` / `jet.pt`, or an explicit `pt` parameter), the same rows the prediction tables carry.
